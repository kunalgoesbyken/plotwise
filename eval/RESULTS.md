# Rule-extraction eval: point vs write

Does making the AI point at source lines (pointers compiled by code) beat having it write the values itself? Generated by `bun eval/score.ts`.

## Methods

point = compiled pack; caught = compile rejections + checkPack. write-n = a classic extraction run; caught = checkPack errors after its values are substituted into the pack (write + check). Ungrounded = answers whose quote is not in the cited source or whose value is not on the cited page. Value not in own quote = answers whose quote does not contain the value given.

## Limits

- Ground truth comes from secondary published sources (re-published law text, PDF copies, Thai real-estate articles), with a verbatim quote for each value. It was not hand-typed by a human from the gazette. Source notes: The article covers the bonus measures under the draft revision of the plan; it is used here as evidence for the 2556 measure.
- Coverage of the truth set: 87 of 133 fields, from 11 distinct URLs. Fields with no independent source are scored only by agreement: far.max, openSpaceRatio.minShareOfFloorArea, farBonus.combinedMaxShare, farBonus.measures[0].maxShare, farBonus.measures[1].maxShare, farBonus.measures[2].maxShare, useConditions.office.threshold, useConditions.office.unlessRoadWidthM, useConditions.office.unlessStationDistanceM, useConditions.hotel.threshold, useConditions.hotel.unlessRoadWidthM, useConditions.hotel.unlessStationDistanceM, useConditions.roadAccessTiers[0].roadWidthM, useConditions.roadAccessTiers[0].frontageM, useConditions.roadAccessTiers[0].otherEndRoadWidthM, useConditions.roadAccessTiers[0].maxDistanceM, useConditions.roadAccessTiers[1].roadWidthM, useConditions.roadAccessTiers[1].frontageM, useConditions.roadAccessTiers[1].otherEndRoadWidthM, useConditions.roadAccessTiers[1].maxDistanceM, useConditions.roadAccessTiers[2].roadWidthM, useConditions.roadAccessTiers[2].frontageM, useConditions.roadAccessTiers[2].otherEndRoadWidthM, useConditions.roadAccessTiers[2].maxDistanceM, useConditions.roadAccessTiers[3].roadWidthM, useConditions.roadAccessTiers[3].frontageM, useConditions.roadAccessTiers[3].otherEndRoadWidthM, useConditions.roadAccessTiers[3].maxDistanceM, buildingClasses.largeIfTallAboveFloorAreaSqm, boundarySetbacks[1].bands[0].heightM.max, boundarySetbacks[1].bands[0].distanceM, boundarySetbacks[1].bands[1].heightM.min, boundarySetbacks[1].bands[1].distanceM, boundarySetbacks[2].bands[0].heightM.max, boundarySetbacks[2].bands[0].distanceM, boundarySetbacks[2].bands[1].heightM.min, boundarySetbacks[2].bands[1].distanceM, heightVsRoad.maxMultipleOfDistance[1], heightVsRoad.wideRoadException.roadWidthM, heightVsRoad.wideRoadException.withinM, heightVsRoad.wideRoadException.accessWidthM, frontOpenSpace.depthM, frontOpenSpace.tallAboveStoreys, frontOpenSpace.tallDepthM, frontOpenSpace.minShareOfPerimeter, parking[0].largeBuildingSqmPerSpace.
- Ambiguity recall could not be measured fairly: the interpretation questions had already been seen and decided while the pointers were built, so there is no unseen set to recall.
- n = 2 write runs. Run-to-run agreement is a cheap uncertainty signal, not a confidence interval.
- All methods used the same model family, so their errors may be correlated; agreement between them is weaker evidence than agreement with an outside source.
- Values are compared exactly after one normalisation: a share field (path ending in a name containing "share") read above 1 is taken as a percentage and divided by 100. Lengths must be in metres and areas in square metres; nothing else is rescaled. The checks see raw values, so a percentage written as 30 counts as correct against the truth but is still caught by the range check.
- The value-on-page check is lenient: it accepts any number on the cited page, its hundredths (for percentages and centimetres), "x in y" ratios and Thai number words before a unit. Small integers appear on almost every page, so "Ungrounded" is a lower bound on hallucination; "Value not in own quote" is the stricter signal.
- For "write + check", unresolved write fields keep the pack value, so the checks cannot see errors in fields a run left open. For the point method only the final pointers are compiled; rejections made while the pointers were being written are not recorded.
